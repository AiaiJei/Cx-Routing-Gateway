## 产品目标

Cx-Routing Gateway 是桌面程序。用户打开程序时自动启动本机网关，并在桌面工作区管理上游、模型映射、连接测试、调用日志与接入凭证。其他客户端通过显示的网关 URL 和访问 Key 接入。本产品不区分管理员/普通用户角色，也没有独立 Web 管理后台。`docs/concepts/gateway-overview.svg` 是可缩放的静态概念图，配套 `concept-preview.png` 是渲染预览；所有指标均为设计示意数据。

概念图按页面拆分，含静态预览与可缩放 SVG 源文件，见[逐页页面概念图](concepts/README.md)。

## 使用者与主要任务

本产品面向单机使用者，不区分管理员与普通操作员，也不提供独立管理后台。使用者打开 Desktop 程序后，网关自动启动；随后可在同一桌面工作区配置上游与模型路由、测试连通、查看日志，并管理供外部客户端使用的访问 Key。接入方是网关的调用方，不是本桌面程序中的管理角色。

## 协议假设与术语

本蓝图暂将 Res、Mes、Chat 解释为 OpenAI Responses API、Anthropic Messages API、OpenAI Chat Completions API。该解释是待产品 Owner 确认的术语假设，不代表完全兼容或所有协议能力均可互转。协议适配需定义请求/响应映射范围、流式事件、工具调用、图像/多模态、错误码和不支持能力的行为。

## 信息架构

- 总览：网关状态、近 24 小时请求/错误/延迟摘要、最近异常与快捷操作。
- 上游：提供方、Base URL、上游协议、Key 引用、可用性、最近测试、模型同步。
- 模型路由：客户端模型别名、客户端入站协议、目标上游/模型、配置的上游出站协议、启停与冲突状态。响应方向固定回转为原入站协议。
- 调用日志：时间、请求 ID、模型、入口 Key、上游、协议方向、状态、耗时、错误摘要；详情中敏感字段默认脱敏。
- 接入凭证：对外网关 URL、访问 Key、权限/模型范围、创建/到期/最近使用、轮换和撤销。
- 设置：本机网关地址与监听范围、启动状态、日志保留、安全策略、协议能力与版本信息。

## 路由核心概念

生命周期与请求路径：用户打开 Desktop 程序 → Desktop 启动本机 Gateway 运行时 → 工作区显示运行状态及本机接入 URL。调用链为接入方 → 网关 URL + 客户端 Key → 按客户端实际请求识别入站协议 → 客户端模型别名解析 → 路由规则读取配置的出站协议 → 请求转换后调用上游 → 将上游响应转换回原入站协议 → 返回客户端并写入使用日志。配置对象分离为上游、客户端凭证、模型路由和协议适配策略。

## 协议方向与路由语义

入站协议由下游客户端实际发送的 API 请求决定，不由上游配置决定。每条路由设置目标上游所需的出站协议。网关把请求从入站协议转换为该路由的出站协议，再将上游响应（含流式响应）转换回原入站协议返回下游。响应协议因此与该次请求的入站协议对应，不另行由上游选择。

示例：任意下游客户端以 Res 发起请求 → 网关识别 Res 入站 → 命中目标模型路由，配置 Chat 出站 → 网关以 Chat 格式请求上游 → 收到 Chat 响应 → 转换为 Res 响应 → 返回原下游客户端。配置界面应分别显示“客户端协议/入站协议”和“上游协议/出站协议”，日志可同时记录请求方向 `Res → Chat` 与响应方向 `Chat → Res`。不支持的协议对或语义能力必须按能力矩阵明确拒绝或注明降级，不能默默返回错误格式。

## 安全与可靠性边界

- 上游密钥和客户端 Key 只在创建/轮换时显示明文；日志及导出不记录明文。
- Key 使用安全哈希或受控密钥存储；明确创建、轮换、撤销和审计语义。
- 不记录请求/响应正文为默认值；若未来支持采样，需提供脱敏、保留期与访问控制。
- 连通测试仅访问使用者配置的上游目标，设置超时、大小限制和结果脱敏，防止 SSRF。
- 统一设置超时、重试边界、并发限制、错误分类与请求关联 ID。
- 协议映射采用能力矩阵；无法无损转换时明确报错或按约定降级，不静默丢失工具/流式内容。

## 生命周期待确认

必须由产品 Owner 决定 Desktop 退出时是否停止 Gateway、是否提供后台常驻/托盘、开机启动和本机以外的网络监听。默认方案暂定网关随 Desktop 生命周期启动与停止、仅监听本机回环地址；如需局域网或远程访问，须单独设计认证与暴露范围。

## 桌面端与网关运行时边界

Desktop 程序负责桌面工作区、配置界面、状态展示与 Gateway 进程生命周期编排；Gateway 运行时负责本机 HTTP 接入、鉴权、路由、协议适配、上游调用和日志。前端可先用本地 fixture 设计状态与交互，后续通过明确的本机 IPC/API 接缝连接真实运行时。概念图是静态设计，不构成功能承诺。
