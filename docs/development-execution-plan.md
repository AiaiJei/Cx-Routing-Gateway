# 开发执行计划

## 执行原则

每个阶段独立开任务合同和验收证据，沿“确认现状 → 最小改动 → 即时检查 → 链路验证 → 独立审查 → Owner 验收”推进。阶段 1 的Desktop UI 先对稳定的本机 IPC/API 合同编码；Gateway 运行时接入时不重写 UI 领域模型，采用适配层迁移 fixture 至真实 API。

## 前端执行顺序

1. 锁定 Desktop 导航、字段字典、表格列、路由规则与三协议能力矩阵。
2. 建立 Desktop 工作区 shell、导航、设计 tokens、表格/表单/状态组件和键盘焦点规范；设计启动中、运行、失败状态。
3. 先实现上游列表/详情及测试、模型映射编辑流程；再实现接入凭证和日志。
4. 以 fixture 展示成功、失败、空、加载、禁用及部分协议不支持状态；明确模拟数据标识。
5. 适配桌面、窄视口和键盘操作；验证颜色对比、表单标签、错误关联及脱敏。
6. 形成 API client 接缝、字段映射和错误格式契约；不把后端假响应写进组件。

## 后端接入执行顺序

1. 领域/API schema：上游、模型发现、路由、客户端 Key、日志与审计对象。
2. 存储与迁移：配置版本、加密凭证引用、事务及回滚策略。
3. 控制面：RBAC、上游 CRUD、模型发现、受限连通测试、Key 生命周期。
4. 数据面：入站认证 → 按客户端请求识别协议 → 路由读取配置的上游出站协议 → 请求转换并转发 → 响应/流式转换回原入站协议 → 日志同时记录两方向。
5. 为每个协议和上游实现契约测试；先非流式，再流式和工具调用，逐项验证兼容表。重点覆盖通用客户端 Res 入站 → Chat 出站 → Res 响应回转，以及其他协议组合和不支持映射的明确失败。
6. 联调 Desktop 启动器与 Gateway 生命周期；验证限流/超时/错误边界、脱敏和 SSRF。
7. 灰度启用，观察错误率/延迟/资源；保留关闭适配器和配置回滚步骤。

## 生命周期决策待确认

- Desktop 关闭后 Gateway 停止，还是后台/托盘常驻。
- 是否支持开机启动与崩溃恢复。
- Gateway 是否仅监听本机回环地址，是否允许局域网访问。

## 回退与停止条件

若协议合同不明确、认证/密钥方案未审查、能力矩阵与实现冲突或敏感字段进入日志，暂停扩展并记录 BLOCKED；回退至最近兼容版本或关闭单个适配器。不得以静态页面存在推断服务可用，也不得以 mock 成功作为链路通过。
