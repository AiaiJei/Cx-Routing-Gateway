# 开发计划

## 范围

按“前端先行、后端接入”的顺序交付桌面网关程序。Desktop 打开时自动启动本机 Gateway；桌面工作区包含总览、上游、模型路由、连通测试、模型同步、日志、接入 URL/Key；后端阶段实现持久化、安全鉴权、协议适配和运行时转发。本计划不授权当前规划任务实施这些功能。

## 阶段与依赖

| 阶段 | 交付 | 依赖 / 出口条件 |
|---|---|---|
| 0. 需求与协议合同 | Res/Mes/Chat 术语确认；协议能力矩阵；领域对象和接口草案 | Owner 确认协议含义、桌面技术形态、Gateway 生命周期与监听范围、单实例/后台策略；完成威胁建模 |
| 1. 前端体验 | 桌面工作区界面、导航、组件/样式基线、fixture、加载/空/错误/网关启动状态、可访问性 | 蓝图/概念图确认；暂用 fixture，禁止假称生产成功 |
| 2. 本机控制 API / IPC | 上游 CRUD、模型发现、连通测试、路由规则、客户端 Key 生命周期 | API schema、数据库迁移、本机调用边界、配置保护、SSRF 与密钥方案通过审查 |
| 3. 数据面转发 | 三协议接入和出站适配、模型路由、流式处理、超时/限流、错误语义 | 协议合同与兼容矩阵；上游适配器契约测试通过 |
| 4. 日志与运维 | 使用日志、筛选/详情、指标、保留策略、诊断文档 | 脱敏审查、日志量/成本界限、可观测性验收 |
| 5. 发布准备 | 部署配置、迁移/回滚、运维手册、安全和性能验收 | 全量验收清单通过；明确发布/回滚负责人 |

## 建议领域模块

- `gateway`: 入站认证、请求上下文、管线组装。
- `routing`: 模型别名、从入站请求到配置出站协议的路由选择、响应回转策略校验。
- `protocols`: Res/Mes/Chat 协议解析、规范化表示及流式事件转换。
- `upstreams`: 上游配置、模型发现、健康/连通测试、凭证引用。
- `credentials`: 客户端 Key 创建、校验、轮换、撤销与权限范围。
- `usage`: 请求摘要、错误、延迟与脱敏日志。
- `control-plane`: 管理 API、授权、审计和配置存储。

## 风险与控制

协议语义不对称、流式边界、工具调用差异、密钥泄露、SSRF、上游速率限制和高基数日志是主要风险。采用能力矩阵与明确失败策略；网络目标白名单/地址校验；密钥仅回显一次；结构化日志字段白名单；对适配器进行契约/边界测试。

## 回退

前端可按页面/功能开关回退到只读或 fixture 演示；控制面通过向后兼容迁移与配置快照回滚；数据面按协议/上游适配器粒度禁用；桌面退出行为按已确认的生命周期策略执行。Key 撤销和安全修复不可通过回滚重新开放已泄露凭证；需轮换并审计。
