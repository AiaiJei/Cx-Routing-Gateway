# 模型分类设计

任务：CXRG-MODEL-FAMILY-2026-11-20。基于 PR #8 合并提交 7e3c4db；用户直接授权实现两处分类并创建独立 PR。以下细节由实现者确定，Owner 验收待定。

## 范围与方案

路由管理者需要在已有路由和上游发现的长模型列表中快速定位模型。沿用 React/TypeScript、现有中性界面、CustomSelect 和按钮样式。七类顺序固定为 gpt、claude、gemini、glm、deepseek、kimi、其他；另有默认“全部”。计数从实际数据计算。

采用纯领域分类函数 + 界面派生状态。相比持久化分类，它可立即覆盖旧路由与每次加载的模型，无需配置迁移；相比两处各自判断，共享规则保持一致。人工管理分类不在本次需求内。

- 匹配不区分大小写，支持供应商命名空间、版本数字和常见分隔符；GPT/ChatGPT 及 OpenAI o1/o3/o4 归 gpt，ChatGLM 归 glm，Moonshot 归 kimi。未知型号归其他，原始 ID 不被改写。
- 路由按当前列表显示的首个上游模型分类；没有目标时使用调用名。分类仅改变展示，不影响故障切换和请求路由。
- 路由表上方展示全部及七类按钮和数量；当前分类显示结果数量，空分类给出明确提示。新增、删除、保存后重新计算。
- 每个上游的 ModelSelect 独立筛选；全部视图按七类顺序分组，空分组不展示。CustomSelect 复用键盘及多选逻辑。
- 切换分类只隐藏选项，触发器仍显示完整选择数量；编辑补入已选但从发现目录消失的模型。分组标题不参与键盘选项索引；Escape、方向键、回车和隐藏表单值保持正常。

实现者负责领域规则、组件、页面接线、测试、浏览器检查和档案。计划包含独立只读审查；若审查服务不可用，则另行自查并明确标记非独立。仅用现有依赖；网络/鉴权/存储/协议接口保持既有调用关系。保留主工作区已有未跟踪目录。
