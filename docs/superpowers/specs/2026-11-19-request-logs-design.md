# 请求日志 1.0.2 设计

用户请求是本设计的授权依据：基于已合并 PR #6，将版本 1.0.1 递增为 1.0.2，建立独立 PR，实现所列请求日志调整。

## 范围与呈现

沿用 PR #6 的工作区、字体、色板、表格、搜索/筛选、Modal、ProtocolBadge，新增一个可复用只读 Tooltip。时间/协议/Token 可悬停、聚焦或点击展开，Escape/离开关闭；浮层 portal 到 body，避免内部滚动容器裁切。请求 ID 可选择复制。

表格：请求时间 | 模型 | 入口凭证 | 入站 | 类型 | Token | 结果 | 耗时 | 详情。
时间用本机时区 YYYY-MM-DD HH:mm:ss；浮层显示完整 ID、原始时间与时区。协议单元仅入站标记，浮层显示入站→上游→响应和上游。类型为流/非流，旧记录未知为 —。Token 为输入、输出、缓存读/写四个 outline SVG+完整数字（两行两列），浮层额外展示总量、推理、音频及缓存时长细分。耗时上下两行分别首字、总耗时；详情复用相同指标。

## Approaches

选择扩展现有 usage 记录和 runtime adapter。纯 UI 会令新指标始终缺失；新增日志 API 会重复已存在的 control state/IPC。采用既有链路并添加可选字段，兼容旧文件；未改变 schema version。

Gateway 新模块负责有限数值字段归一化和有界 SSE 观察，不保存正文、提示词或原始 usage 对象。Chat/Res/Mes 各按上游协议解释 usage；累计字段用最新有效值替换，Mes 的 start/delta 合并，不重复相加。不存在/非法值为缺失，明确 0 保留。缓存输入口径遵循提供方，不能盲目相加成总量。

首字是从 Gateway 收到请求到首个有效生成内容事件（文本、拒绝、推理或工具内容）的时间，不把 SSE 心跳、角色、usage、结束事件计作首字。非流/无生成事件保持缺失，不用总耗时冒充。时间戳改为请求起始时间；旧记录保持原值。记录失败请求时保留已收集的指标。
