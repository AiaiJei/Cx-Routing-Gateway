# 总览重构设计

日期：2026-11-26

状态：Owner 已于 2026-11-26 确认方向；功能实现和本机可验证项已完成。

## 目标

让 Gateway 使用者打开总览后，能迅速回答三个问题：本机 Gateway 是否运行、最近请求表现如何、现在是否有需要处理的失败。页面继续使用真实本机数据；示例数据始终明确标注，不把配置状态说成实时健康。

## 已确认现状

- `OverviewPage` 已显示 Gateway 状态、工作区上游/路由/凭证数量、请求结果汇总、失败记录和最近三条日志，但没有图表。
- `useWorkspace` 同时提供 `meta.live`、Gateway 指标、配置项和带时间戳的 usage 日志。Local Control 的汇总指标按已保留的 usage 记录计算；没有独立的时序指标接口。
- 上游的“已连接”来自最近一次检查标记，不是持续探活；总览不能把它呈现成“当前在线”的保证。
- 现有桌面界面已采用 Geist、白底、灰阶分隔和蓝色强调色。本任务保留共享侧栏、顶部区域、导航和全局字体，不改其他页面。

## 屏幕要回答的问题

按 Owner 后续反馈，第一屏以用量统计和模型调用分析为主，调用量、结果、成功率和 Token 覆盖直接对应同一批日志。Gateway、配置状态、24 小时趋势和最近调用保留在后续区域，失败记录紧邻“查看日志”入口。

## 视觉方向

- **方向：** 采用 Achromatic Ledger 的低装饰数据呈现：平面分隔、数字直接排版、单一图表色，避免 KPI 磁贴、渐变和装饰性火花线。该方向适合短时查看运行状态和请求指标。
- **边界：** 参考样式自带的开放式侧栏与无顶栏壳层不适用于这次单页重构；保留 Gateway 现有壳层，不把整套外部样式复制进来。
- **独有识别：** 主图展示真实 Gateway 请求的时间分布，最近调用继续使用项目已有的协议流组件；不插入虚构的部署、用户或容量数据。
- **基础颜色：** 白底 `#FFFFFF`、浅灰面 `#F7F7F8`、正文 `#252629`、次级文字 `#65676E`、分隔线 `#E9E9EC`、数据蓝 `#0066CC`。成功、失败和待处理只沿用现有状态色。
- **字体：** 沿用 Geist Variable；请求 ID 和短标识继续用现有等宽字体。数值保持表格数字对齐。
- **对齐：** 采用左对齐和现有页面内容边距；大屏按数据关系分栏，小屏单列堆叠。

## 页面结构

### Owner 视觉反馈修订（2026-11-26）

Owner 对原版视觉层级不满意，并确认继续按“图标占比 > 数值 > 状态”调整。Gateway 与上游图标采用 48px，配置和请求指标图标采用 40px；配置数值 24px、上游数量 26px、请求指标 28px；状态和说明采用 12–13px。图标复用现有线性风格，保持数据含义、页面分区和共享壳层。实际宽窄屏渲染与尺寸检查记录在 `visual-icon-hierarchy/` 证据目录；Owner 最终视觉验收仍待进行。

```text
总览  [查看上游 · 查看路由 · 查看凭证]
用量统计                                  [统计范围 · 刷新数据]
调用总数       成功 / 未成功       已上报 Token       平均耗时
输入 Token     输出 Token         缓存读取            缓存写入
各项上报覆盖与统计口径
模型数据分析                              [查看调用日志]
模型 / 最近调用    调用量    成功 / 未成功    成功率    Token    耗时
┌ Gateway 运行状态与监听地址 ─┬ 上游最近检查 ┬ 路由与凭证摘要（各自状态） ┐
└─────────────────────────────┴─────────────┴─────────────────────────┘
┌ 最近 24 小时请求记录（约 2/3 宽） ┬ 需要关注 / 查看日志（约 1/3） ┐
└──────────────────────────────────┴──────────────────────────────┘
最近调用（沿用现有表格与协议流）
```

快捷操作位于标题行；大屏使用现有内容宽度和网格间距，不新增卡片阴影；首屏露出用量统计和模型分析首行。约 390px 宽时，统计指标与 Token 明细各为两列，模型表在自身容器内横向滚动并固定模型名称列；Gateway 与配置状态依次堆叠，日志表保留横向滚动与键盘可达性。

## 数据与状态

### 用量与模型调用修订（2026-11-26）

Owner 要求继续补充用量统计、模型调用分析、状态与数值。总览先展示用量，再展示按请求模型标识聚合的调用分析，Gateway 与配置状态保留为辅助区。统计范围提供“已保留记录”和“最近 24 小时”；调用数、成功/失败、成功率、耗时和模型行从同一批日志计算，不混入范围不同的 Gateway 总计。模型调用量用从零起点的横向 SVG 条形展示，数值与表格共同提供可访问信息；默认显示调用最多的五个模型，可展开全部。

Token 仅汇总已有上报字段，展示输入、输出、缓存读取、缓存写入和总量；每项标注上报条数，缺失为“—”，有效零值为 0。缓存或推理字段不重复加到总量，也不以输入和输出推算供应商未上报的总量。不新增费用估算或上游请求。已有刷新能力复用到统计区，刷新中禁用重复操作，失败保留旧数据并明确提示。

由当前代理负责聚合、页面和验证，独立审查使用单独审查者且与本机测试分开记录。验收包括范围边界、按模型合计、缺失/部分/零用量、无数据、刷新反馈、宽窄屏和长模型名。继续在原工作树和 PR #27 交付；回退以本轮前提交 `2698250` 为比较基线，未获授权不重置主分支或删除工作树。

- 汇总数与模型行统一从选中范围的日志计算，不混入范围不同的 Gateway 汇总值；保留“示例数据 · 非实时”提示。总 Token 仅累计 `tokens.total`，输入/输出不用于推算缺失总量，缓存与推理不重复累加。
- 主图按 `CallLog.time` 统计滚动 24 小时内每小时的已记录请求。它代表当前返回的日志记录，不伪称独立的全量时序数据；若记录数达到当前保留上限，图表旁明确提示覆盖范围可能不完整。坏时间戳不进入图表，但不影响日志行。
- 数据映射通过可选的 `usageRetentionCount` 暴露运行时保留上限，图表按数值比较，不解析设置页的展示文案；该上限缺失时不显示完整性判断。
- Gateway 状态用文字与现有语义色同时表示；路由显示启用/停用数量，凭证区分有效/已撤销。上游状态文案注明是最近检查结果，不主动发起网络探测，也不声称持续健康。
- 加载和失败沿用 `WorkspaceState`；无请求时图表显示有说明的空状态；有效的零值显示为 `0`，缺失耗时显示短横线。状态不能只靠颜色区分。

## 组件与验证

- `OverviewPage` 负责组装状态、摘要、失败入口和最近调用。
- 新增纯函数 `apps/desktop/src/domain/overview-usage.ts` 汇总时间桶与保留上限提示；不新增服务端接口或图表依赖。
- `OverviewUsageChart` 负责 SVG 绘制、刻度、可访问名称和窄屏布局。
- `overview-analytics` 负责范围筛选、用量覆盖和模型聚合；`OverviewUsageStats` 负责统计与刷新控制；`OverviewModelAnalysis` 负责模型排行与表格。复用既有日志数值校验和格式化函数，不新增数据接口。
- 单测覆盖 24 小时边界、无记录、无效时间戳、失败/成功数据、达到保留上限；页面测试覆盖实时/示例状态、运行失败、空日志和导航链接。
- 功能实现后运行定向测试与桌面生产构建；在 1440×900 和 390px 真实渲染检查文本、图表、键盘焦点和溢出，再做独立审查。测试与截图不代表 Owner 的最终产品验收。
