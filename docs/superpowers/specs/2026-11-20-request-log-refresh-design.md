# 请求日志刷新 · 1.0.3

任务：CXRG-LOG-REFRESH-2026-11-20。依据用户 2026-11-20 明确需求，以 PR #7 合并提交 `272e443` 为基线；产品版本从 1.0.2 升级到 1.0.3，提交专属 PR。

## 范围与选择

- 日志页标题右侧复用 `PageHeader.action`、`Button`，增加“刷新”。手动读取中禁用按钮并显示“刷新中…”。后台轮询不反复播报或替换页面。
- 在共享 `useWorkspace` 增加可选轮询和手动刷新，只有日志页启用 1500 ms 间隔。沿用 `WorkspaceClient.getWorkspace()` → Desktop IPC → 本机 control API 的鉴权/脱敏链路，不增加接口或依赖。
- 每个 tick 在页面可见且没有在途读取时取新快照。隐藏时暂停，重新可见时立即刷新，卸载清理 timer/listener 并忽略旧响应。1–2 秒目标指日志已落盘且本机读取正常的可见页面；慢 IPC 会增加延迟。
- 首次加载失败不显示示例数据，保留刷新入口并自动重试。后续失败保留上次成功数据、搜索、状态筛选和打开的详情，提示失败并允许手动/自动恢复。
- 不启用全局轮询，不改变日志采集、存储、鉴权、正文脱敏及其他页面的默认加载行为。

## Approaches

1. **采用：可选共享 Hook + 1500 ms 轮询。** 复用客户端，入口只负责界面与启用参数；最小范围满足用户指定机制。
2. 日志页复制加载状态：重复错误/生命周期逻辑，且刷新行为难以复用。
3. 推送 IPC/SSE：需改协议/订阅链路，当前功能无需扩大到后端。

以上技术细节由实现者依据现有接口决定；用户已明确授权本功能和专属 PR。

## 2026-11-20 修订：最新优先与日期筛选

用户在已启动的 1.0.3 窗口验看后要求“第一条为最新”及“实时、今日、近7天、近30天”。继续 PR #8，版本仍为 1.0.3。

- 数据按时间戳倒序，先解析真实时间再比较（包含带时区的 ISO 时间）；同一时间保留来源顺序。无效时间放在末尾，不修改底层日志数组或存储顺序。
- 工具栏复用 `SegmentedControl`，日期筛选与搜索、成功/失败筛选取交集；清除筛选同时回到实时、全部状态和空搜索。
- 实时：全部已保留记录。今日：本机今日 00:00 到当前时刻。近7/30天：从本机前6/29日 00:00 到当前时刻，包含今天，使用日历运算适配跨月/年与夏令时。无效日期不能归入日期范围，只在实时展示。
- 每个范围仍使用原有 1500 ms 轮询，保留所选范围和详情；刷新会重算当前日期，因此跨午夜不滞留上一日范围。
- 采用独立纯查询模块 `domain/request-log-filter.ts`，负责筛选及排序。日志页只组装状态和共享控件。相比修改存储/API顺序或在 JSX 内堆叠规则，该方式影响局限于日志展示，也便于验证时区/边界。
- 主代理实现/测试；独立审查只读检查本修订；验收含边界、筛选交集、轮询新记录置顶、午夜切换、三尺寸浏览器和新版 Desktop 启动。回退本修订提交并启动保留的旧包即可。
