# Request body 413 fix implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Forward model requests larger than the previous 1 MiB Gateway limit while retaining an explicit bounded oversized-request error.

**Architecture:** Make the inbound body ceiling a validated server option with a 64 MiB default and an environment override. Preserve byte counting and UTF-8 decoding, reject declared oversized bodies before buffering, and document the operator setting.

**Tech Stack:** Node.js HTTP server, node:test, existing ConfigStore and SecretVault fixtures.

**Spec:** `docs/superpowers/specs/2026-11-21-request-body-413-design.md`

## Global Constraints

- Keep the Gateway bound; do not introduce unbounded buffering.
- Do not change routing, protocol conversion, credentials, storage, usage schema, product version, release, or deployment.
- Error code is exactly `request_body_too_large`; default limit is exactly `64 * 1024 * 1024` bytes.
- Preserve existing 30-second request-body timeout behavior.

## Review Focus

- A request just above 1 MiB must reach the upstream with the same text.
- A request above an explicitly injected limit must return 413 and never reach the upstream.
- A UTF-8 character split across chunks must not be corrupted.
- Invalid environment or option values must fail during server construction rather than silently disabling the bound.
- A declared oversized Content-Length must be rejected before the body is buffered.
