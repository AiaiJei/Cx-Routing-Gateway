# Cx-Routing Gateway 1.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare PR #10 and a verified Windows x64 1.1.0 release with private GitHub Release updates, a product icon, and a single-file portable executable on GitHub Releases and the user's Desktop.

**Architecture:** Keep the repository private and let each authorized app user provide a fine-grained `Contents: Read` token. The Electron main process validates it against the fixed repository, encrypts it through `safeStorage`, and supplies it only as an Authorization header to GitHub API and asset requests. Settings receives only configured/update status. electron-builder creates a Windows x64 `portable` target so users double-click one self-extracting `.exe` without installing or manually extracting an archive.

**Tech Stack:** Electron 45 `safeStorage`/IPC, electron-builder portable target, Node.js built-in fetch/crypto/test, React/Vitest, PowerShell PE verification.

**Spec:** `docs/superpowers/specs/2026-11-20-release-1.1.0-design.md`

## Global Constraints

- Product version is `1.1.0`; repository remains private.
- Users configure a repository-scoped GitHub fine-grained token with only `Contents: Read`.
- Token flows only from the password field through trusted IPC into Electron main; encrypted `safeStorage` data is stored separately in user data; never fall back to plaintext.
- Never return, log, include in URLs, commit, or package the token. Clear the input after save.
- Stable Release API is the update source; the NSIS installer remains user-initiated and must match GitHub's SHA-256 digest before execution.
- Build a single Windows x64 portable `.exe` that runs directly without an installer or manual ZIP extraction; place a hash-verified copy on the Desktop.
- Use existing isolated repo-local worktree `.worktree/release-1.1.0` and branch `codex/release-1.1.0`; preserve unrelated paths and worktrees.
- PR creation and release publication are requested; do not merge PR #10 or change/delete a release tag without separate owner authorization.

## Review Focus

- Safe-storage unavailable or a decrypt failure must not expose a plaintext fallback. Test save refusal, encrypted bytes, and decryption failure in Task 1.
- Unauthorized/missing/revoked tokens must yield a clear setup/access error without being persisted or returned. Test in Tasks 1–2.
- GitHub metadata and asset requests must carry credentials only in Authorization headers to the fixed GitHub hosts; no token in URLs, logs, returned metadata or renderer responses. Task 1 asserts the request URL has no query/token, both requests use the header, and neither check/download results contain the token.
- Drafts/prereleases, malformed tags, missing assets/digests and tampered bytes must never offer/install an update. Test in Task 1.
- Portable packaging must include runtime resources, remain x64, launch from its single `.exe` without manual extraction, and not contain the stored token. Verify in Task 3.

- `scripts/check-update.mjs`: repository access validation, stable Release lookup, version comparison and digest-verified installer download.
- `tests/runtime/github-token-store.test.mjs`, `tests/runtime/check-update.test.mjs`: safe-storage and GitHub HTTP fixture tests.

- `apps/desktop/build/icon.svg`, generated `icon.ico`, `electron-builder.yml`: product icon source and packaging configuration.
- `apps/desktop/package.json`, `package-lock.json`: version `1.1.0`.
- `scripts/package-portable.ps1`, `scripts/smoke-portable.mjs`, `scripts/verify-release.mjs`: single-file x64 portable generation and verification.

**Interfaces:**
- `createGitHubTokenStore({ filePath, safeStorage, fsImpl })` returns async `hasToken()`, `getToken()`, `setToken(token)`, and `removeToken()` methods.
- `verifyGitHubToken({ token, repository, fetchImpl })` validates the required Contents permission through authenticated `GET /repos/{owner}/{repo}/contents` and returns only `{ valid: true }`.
- `createGitHubTokenService({ store, safeStorage, verifyToken })` returns `getStatus()`, `save(token)`, `getToken()`, and `remove()`; `save` verifies access before calling `store.setToken`.
- `checkUpdate({ currentVersion, token, repository, fetchImpl })` and `installUpdate({ currentVersion, token, repository, fetchImpl, downloadDir })` require a token and use it only in request headers.
